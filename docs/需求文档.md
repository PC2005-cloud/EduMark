# 基于大模型的中小学作业批改系统 — 需求文档

## 1. 项目概述

### 1.1 项目背景
开发一套能够自动识别和批改中小学生作业的智能批改系统，利用计算机视觉、OCR 技术和大语言模型，实现从作业图像采集到最终评分批注的全自动化流程。

### 1.2 项目目标
- 实现作业图像的自动采集、校正、增强和切割
- **双识别引擎架构**：
  - **引擎一**：阿里云 RecognizeEduPaperCut（切题）+ RecognizeEduQuestionOcr（题目 OCR）
  - **引擎二**：百炼平台视觉理解模型（端到端图像理解）
- 调用大模型 API 对答案进行智能批改
- **基于向量知识库的检索增强批改**：构建学科知识库，批改时检索相似知识点作为参考依据
- **完整的用户管理体系**：支持多角色（管理员 / 教师 / 学生）的注册、认证和权限控制
- 系统具备高并发处理能力

### 1.3 技术栈
| 层面 | 技术选型 |
|------|----------|
| 后端框架 | FastAPI (Python) |
| 图像处理 | OpenCV, Pillow |
| 识别引擎一（传统 OCR） | 阿里云 RecognizeEduPaperCut + RecognizeEduQuestionOcr |
| 识别引擎二（视觉理解） | 百炼平台视觉理解模型（Qwen-VL 系列） |
| 批改引擎 | 大模型 API (如通义千问 / ChatGPT / Claude) |
| 向量数据库 | Milvus / Qdrant / Chroma |
| 向量化模型 | text2vec / BGE / 通义千问 Embedding |
| 文档解析 | MinerU（PPT / PDF / Word 解析为结构化文本） |
| 知识管理 | 知识分块、异步索引、版本管理 |
| 用户认证 | JWT + OAuth2 密码模式, 密码哈希（bcrypt / passlib） |
| 关系数据库 | PostgreSQL / MySQL（用户、班级、作业、成绩等） |
| ORM | SQLAlchemy / Tortoise-ORM |
| 并发处理 | Celery + Redis / 异步任务队列 |
| 对象存储 | MinIO（作业图片、批注结果图片存储） |
| 部署 | Docker + Nginx |

### 2.4 识别引擎一：阿里云 OCR 管线

#### 2.4.1 题目切分（RecognizeEduPaperCut）
| 功能 | 描述 |
|------|------|
| 试卷切题 | 调用阿里云 API 将整页作业切割为独立题目区域 |
| 结果解析 | 解析 API 返回的题目位置坐标和置信度 |
| 区域裁剪 | 根据坐标信息从原图中裁剪出每道题目的子图 |

#### 2.4.2 题目 OCR 识别（RecognizeEduQuestionOcr）
| 功能 | 描述 |
|------|------|
| 文字识别 | 对每道题目子图调用 OCR API 提取题目文本 |
| 结构保留 | 保留题目中的公式、图表等结构化信息 |
| 答案提取 | 从识别结果中分离出学生手写答案区域 |

### 2.5 识别引擎二：百炼平台视觉理解模型

#### 2.5.1 方案说明
直接使用百炼平台的视觉理解模型（如 Qwen-VL-Max / Qwen-VL-Plus），将作业图像输入模型，由模型端到端完成题目理解、文字提取和答案识别，无需经过独立的切题和 OCR 步骤。

#### 2.5.2 功能设计
| 功能 | 描述 |
|------|------|
| 图像输入 | 将预处理后的作业图像直接发送给百炼视觉模型 |
| 题目理解 | 模型自动识别题目区域、题目内容和学生作答 |
| 结构化输出 | 模型返回按题目编号的结构化识别结果（题目内容 + 学生答案） |
| 图文混合识别 | 支持识别题目中的图片、公式、图表等非纯文本元素 |

#### 2.5.3 Prompt 策略
| 场景 | 说明 |
|------|------|
| 整页理解 | 一次性输入整页图片，模型直接输出所有题目的识别结果 |
| 逐题理解 | 先由预处理模块粗切分，再逐题送入模型，提升精度 |

### 2.6 双引擎选型策略
| 维度 | 阿里云 OCR 管线 | 百炼视觉模型 |
|------|----------------|-------------|
| 识别粒度 | 切题 → OCR 两步走，结构化清晰 | 端到端理解，一次调用 |
| 题型适配 | 对标准试卷切题效果好 | 对自由排版、手写混合场景灵活 |
| 公式/图表 | OCR 对公式支持有限 | 视觉模型可直接理解 |
| 成本 | 按 API 调用次数计费 | 按 Token 计费 |
| 延时 | 多步串行，延时累积 | 单次调用，延时更低 |

**策略**：系统支持两种引擎可切换，用户提交时指定使用哪种方式，或系统根据图像复杂度自动择优。

### 2.7 知识库模块（RAG 检索增强）

#### 2.7.1 概述
构建学科知识库，将教材、教案、标准答案、常见错题解析等知识向量化存储。批改时，根据题目内容检索最相关的知识片段，作为大模型批改的参考依据，提升批改的准确性和可解释性。

#### 2.7.2 知识库构建

知识入库流程：
```
PPT / PDF / Word → MinerU 解析 → 结构化文本 → 知识分块 → Embedding → 向量库
```

| 功能 | 描述 |
|------|------|
| 知识来源 | 教材章节、教案讲义（PPT/Word）、标准答案集、常见错题集、知识点图谱 |
| 文档解析 | 教师上传 PPT/PDF/Word，由 MinerU 自动解析提取结构化文本内容，保留章节层级 |
| 知识分块 | 按章节/知识点粒度对解析后的文本进行智能分块（Chunking），保留上下文关联 |
| 向量化索引 | 调用 Embedding 模型将文本块转为向量，写入向量数据库 |
| 元数据标注 | 每个知识块标注学科、年级、章节、知识点标签，支持过滤 |
| 版本管理 | 知识库支持增量更新和版本回退 |

#### 2.7.3 检索策略
| 功能 | 描述 |
|------|------|
| 语义检索 | 将题目文本向量化，在知识库中检索 Top-K 最相似知识片段 |
| 混合检索 | 向量相似度 + 关键字 BM25 加权融合 |
| 学科过滤 | 按学科/年级预过滤，缩小检索范围，提升命中率 |
| 重排序 | 对粗召回结果进行重排序（Re-Rank），提高 top-K 质量 |

#### 2.7.4 检索增强批改流程
```
题目文本 → 向量化 → 知识库检索 → Top-K 知识片段
                                      ↓
                    学生答案 + 题目 + 知识片段 → LLM 批改 → 评分 + 评语 + 知识引用
```

### 2.8 智能批改模块（基于 RAG）

#### 2.8.1 批改流程
```
题目文本 + 学生答案
        ↓
向量知识库检索 → 获取 Top-K 相关知识片段
        ↓
组装 Prompt → 调用大模型 API → 批改结果
```

#### 2.8.2 功能设计
| 功能 | 描述 |
|------|------|
| 知识增强 | 从知识库检索与题目相关的知识点，注入批改 Prompt 作为参考依据 |
| 答案比对 | 基于知识库检索到的相关知识，对学生答案进行语义比对和正误判断 |
| 评分规则 | 支持按知识点给分、分步给分、全对/全错等多种评分模式 |
| 批改结果 | 输出每道题的得分、扣分点、批改评语及所引用的知识来源 |
| 科目适配 | 支持语文、数学、英语等主要科目的批改逻辑差异化 |
| 可解释性 | 批改结果附带知识引用来源，便于教师复核 |

### 2.9 高并发支持
| 功能 | 描述 |
|------|------|
| 异步处理 | 使用 Celery 任务队列异步处理作业批改请求 |
| 请求排队 | 基于 Redis 的请求队列管理，防止系统过载 |
| 水平扩展 | 支持多 Worker 实例并行处理 |
| 限流熔断 | 对第三方 API 的调用限流和熔断保护 |
| 结果回调 | 支持异步回调通知批改完成 |

### 4.1 核心流程
1. 用户上传/拍摄作业图片 → FastAPI 接收请求
2. 图像预处理（校正、增强、分割）
3. **识别阶段**（按所选引擎分流）：
   - **引擎一（阿里云 OCR）**：调用 RecognizeEduPaperCut 切题 → 对每道题调用 RecognizeEduQuestionOcr 识别
   - **引擎二（百炼视觉模型）**：将图像送入 Qwen-VL 模型，端到端输出题目内容和学生答案
4. **知识检索阶段（RAG）**：
   - 将题目文本向量化，在知识库中检索 Top-K 相关知识片段
   - 结合学科/年级元数据进行过滤
5. **批改阶段**：将题目 + 学生答案 + 知识片段组装为 Prompt，调用大模型 API 逐题批改
6. 返回批改结果（含每道题的得分、评语和知识引用来源）

## 7. 测试要求

- 在给定的测试样本集上测试并报告测试结果
- **识别引擎对比测试**：在相同样本集上对比两种引擎的性能
  - 引擎一（阿里云 OCR）：统计切题准确率、OCR 识别准确率
  - 引擎二（百炼视觉模型）：统计题目识别准确率、答案提取准确率
  - 对比维度：准确率、单题处理延时、成本消耗
- **批改准确率**：批改结果与人工批改的一致性比率（分有/无知识库增强两组对比）
- **知识库检索评估**：检索命中率（Recall@K）、检索内容与批改结果的相关性
- **性能指标**：单次处理全流程耗时（分引擎统计）
- **并发压测**：测量不同并发数（10 / 50 / 100 / 200）下的吞吐量和响应时间
