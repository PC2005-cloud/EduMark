# 数据库设计

## 1. 概述

本文档定义 EduMark 作业批改系统的数据库结构，包含 9 张关系表。

- **关系数据库**：PostgreSQL / MySQL
- **向量数据库**：Qdrant（知识块向量存储）
- **ORM**：SQLAlchemy

---

## 3. 表详细说明

### 3.1 user — 用户表

**用途**：存储系统所有用户账号，一张表通过 role 区分三类角色。

| 字段 | 类型 | 约束 | 说明 |
|------|------|------|------|
| id | Integer | PK | 主键 |
| account | String | UNIQUE, NOT NULL | 登录账号 |
| username | String | NOT NULL | 显示用户名 |
| email | String | UNIQUE | 邮箱 |
| password | String | NOT NULL | bcrypt 密码哈希 |
| role | String | NOT NULL, DEFAULT 'student' | student / teacher / admin |
| is_active | Boolean | DEFAULT TRUE | 账号是否启用 |
| created_at | DateTime | NOT NULL | 创建时间 |
| updated_at | DateTime | NOT NULL | 更新时间 |

**关系**：
- 一个 user 有多个 task（学生提交作业）
- 一个 user 有多个 knowledge 记录（教师上传知识文档）

---

### 3.2 task — 作业任务表

**用途**：记录每次作业提交，是整个批改流程的核心入口。`task_id`（UUID）是对客户端暴露的唯一标识，自增 `id` 仅内部使用。

| 字段 | 类型 | 约束 | 说明 |
|------|------|------|------|
| id | Integer | PK | 内部自增主键 |
| task_id | String | UNIQUE, NOT NULL | 对外 UUID |
| user_id | Integer | FK → user.id | 提交作业的学生 |
| subject | String | | 科目（math / chinese / english） |
| grade | String | | 年级 |
| mode | String | NOT NULL | 识别模式：aliyun / bailian |
| status | String | NOT NULL | 任务状态 |
| created_at | DateTime | NOT NULL | 创建时间 |
| updated_at | DateTime | NOT NULL | 更新时间 |

**状态流转**：
```
排队中 → 预处理中 → 切题中 → 识别中 → 批改中 → 已完成
                                                      ↘ 失败
```

**关系**：
- 一个 task 对应一个 user（提交者）
- 一个 task 有多个 image（作业图片）
- 一个 task 有多个 question（题目列表）

---

### 3.3 image — 作业图片表

**用途**：存储作业相关的图片路径。每张图片对应一条记录，通过 task_id 关联到具体任务。

| 字段 | 类型 | 约束 | 说明 |
|------|------|------|------|
| id | Integer | PK | 主键 |
| task_id | String | FK → task.task_id | 所属任务 |
| url | String | NOT NULL | MinIO 图片路径 |
| created_at | DateTime | NOT NULL | 创建时间 |
| updated_at | DateTime | NOT NULL | 更新时间 |

**关系**：
- 多个 image 属于一个 task

---

### 3.4 block — 题目块表

**用途**：存储阿里云 RecognizeEduPaperCut 切题结果，记录每道题在原图中的坐标区域和裁剪后的子图路径。一个题目可能跨页，因此一个 question 可对应多个 block。

| 字段 | 类型 | 约束 | 说明 |
|------|------|------|------|
| id | Integer | PK | 主键 |
| question_id | Integer | FK → question.id | 所属题目（切题时可为空，OCR 后回填） |
| url | String | NOT NULL | 裁剪后的题目子图 MinIO 路径 |
| x1, y1 | Integer | NOT NULL | 左上角坐标 |
| x2, y2 | Integer | NOT NULL | 右下角坐标 |
| created_at | DateTime | NOT NULL | 创建时间 |
| updated_at | DateTime | NOT NULL | 更新时间 |

**关系**：
- 多个 block 属于一个 question（跨页场景）

---

### 3.5 question — 题目表

**用途**：存储 OCR 识别后的题目内容和学生答案，是批改的目标对象。

| 字段 | 类型 | 约束 | 说明 |
|------|------|------|------|
| id | Integer | PK | 主键 |
| task_id | String | FK → task.task_id | 所属任务 |
| no | String | NOT NULL | 题号（如 "1"、"2a"） |
| question_text | Text | | 题目文本（OCR 识别结果） |
| student_answer | Text | | 学生答案（OCR 识别结果） |
| question_type | String | | 题目类型 |
| created_at | DateTime | NOT NULL | 创建时间 |
| updated_at | DateTime | NOT NULL | 更新时间 |

**关系**：
- 多个 question 属于一个 task
- 一个 question 有多个 block（跨页）
- 一个 question 有一条 correction（批改结果）
- 一个 question 关联多个 knowledge chunk（批改溯源）

---

### 3.6 correction — 批改结果表

**用途**：存储大模型对每道题的批改结果，包含得分、评语和解析。

| 字段 | 类型 | 约束 | 说明 |
|------|------|------|------|
| id | Integer | PK | 主键 |
| question_id | Integer | FK → question.id, UNIQUE | 题目（一对一） |
| score | Decimal | NOT NULL | 得分（每题满分 10 分） |
| result | String | NOT NULL | correct / wrong / partial |
| comment | Text | | 评语 |
| analysis | Text | | 解题分析 |
| created_at | DateTime | NOT NULL | 创建时间 |
| updated_at | DateTime | NOT NULL | 更新时间 |

**关系**：
- 一条 correction 对应一个 question（一对一）

---

### 3.7 knowledge — 知识文档表

**用途**：记录教师上传的知识文档（PPT / PDF / Word），追踪解析状态。文档经 MinerU 解析、分块、向量化后存入向量数据库，关系表仅记录元数据。

| 字段 | 类型 | 约束 | 说明 |
|------|------|------|------|
| id | Integer | PK | 主键 |
| user_id | Integer | FK → user.id | 上传教师 |
| title | String | NOT NULL | 原始文件名 |
| url | String | NOT NULL | MinIO 对象路径 |
| subject | String | | 学科 |
| grade | String | | 年级 |
| status | String | NOT NULL | pending / parsing / completed / failed |
| chunk | Integer | DEFAULT 0 | 生成的知识块数量 |
| created_at | DateTime | NOT NULL | 创建时间 |
| updated_at | DateTime | NOT NULL | 更新时间 |

**关系**：
- 一个 user 有多个 knowledge 记录
- 一个 knowledge 生成多个知识块（存在向量库中）

---

### 3.8 question_chunk — 知识块题目关联表

**用途**：记录批改时每题引用了哪些知识块，用于结果溯源和可解释性。批改时大模型检索知识库，命中的知识块 ID 记录在此表。

| 字段 | 类型 | 约束 | 说明 |
|------|------|------|------|
| id | Integer | PK | 主键 |
| question_id | Integer | FK → question.id | 题目 |
| knowledge_id | Integer | FK → knowledge.id | 来源文档 |
| chunk_id | String | NOT NULL | 向量库中的知识块 UUID |
| created_at | DateTime | NOT NULL | 创建时间 |
| updated_at | DateTime | NOT NULL | 更新时间 |

**关系**：
- 一个 question 关联多个 chunk（多对多，通过此表关联）

---

### 3.9 config — 用户配置表

**用途**：存储用户的个性化设置，每个用户一条配置。提交作业时系统自动读取用户配置作为默认参数。

| 字段 | 类型 | 约束 | 说明 |
|------|------|------|------|
| id | Integer | PK | 主键 |
| user_id | Integer | FK → user.id, UNIQUE | 用户 |
| rec_mode | String | NOT NULL, DEFAULT 'aliyun' | 识别模式：aliyun / bailian |
| enable_enhance | Boolean | NOT NULL, DEFAULT TRUE | 是否开启图片增强 |
| vl_model | String | | 视觉模型名称 |
| gl_model | String | | 批改模型名称 |
| create_time | DateTime | NOT NULL | 创建时间 |
| update_time | DateTime | NOT NULL | 更新时间 |

**关系**：
- 一个 user 有一条 config（一对一）

---

### 3.10 模型消息表
**用途**：记录可用的模型信息，用于用户选择。
| 字段 | 类型 | 约束 | 说明 |
| id | Integer | PK | 主键 |
| name | String | NOT NULL | 模型名称 |
| mode | int | NOT NULL | 模型作用（1：提取题目，2：批改题目） |

## 4. 关系汇总

| 左表 | 关系 | 右表 | 说明 |
|------|------|------|------|
| user | 1:N | task | 一个学生提交多次作业 |
| user | 1:N | knowledge | 一个教师上传多份文档 |
| user | 1:1 | config | 一个用户有一条配置 |
| task | 1:N | image | 一次作业有多张图片 |
| task | 1:N | question | 一次作业有多道题 |
| question | 1:N | block | 一道题可能有多个区域块（跨页） |
| question | 1:1 | correction | 一道题只有一个批改结果 |
| question | M:N | knowledge | 通过 question_chunk 关联 |

---

## 5. 核心业务流程与数据流转

```
用户上传图片
    ↓
[task] 创建任务记录（status=pending）
    ↓
[image] 保存图片路径
    ↓
预处理 → 阿里云切题
    ↓
[block] 保存坐标和裁剪图（question_id 暂为空）
    ↓
OCR 识别
    ↓
[question] 保存题目文本和学生答案
    ↓ 回填 block.question_id
[block] 更新 question_id 关联
    ↓
知识库检索 + 大模型批改
    ↓
[correction] 保存得分和评语
[question_chunk] 记录引用的知识块
    ↓
[task] 更新 status=completed
```

## 6. Qdrant 向量库设计

### 6.1 概述

知识块存储在 Qdrant 中，关系表 `knowledge` 仅记录原始文档元数据。Qdrant 作为独立的向量搜索引擎，负责知识块的存储和相似度检索。

### 6.2 Collection 配置

| 配置项 | 值 | 说明 |
|--------|-----|------|
| collection_name | `knowledge_chunks` | 集合名称 |
| vector_size |  1024 | |
| distance | Cosine | 余弦相似度 |
| shard_number | 1 | 单机部署 |
| replication_factor | 1 | 单机部署 |

### 6.3 Payload 字段

Qdrant 的 payload 存储结构化元数据，用于检索时过滤。

| 字段 | 类型 | 说明 |
|------|------|------|
| `document_id` | Integer | 关联 knowledge 表 ID |
| `content` | Text | 知识块文本内容 |
| `subject` | Keyword | 学科（用于过滤） |
| `grade` | Keyword | 年级（用于过滤） |
| `seq_in_doc` | Integer | 在文档中的序号 |
